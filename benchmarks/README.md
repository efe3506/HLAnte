# HLAnte Benchmark Suite

1000 Genomes Project (1000G) benchmark for HLAnte v0.1.0, across 5
super-populations and 4 input-tool formats. Ground truth: **2,693**
Sanger-validated samples (`1000g_HLA_types.tsv`). The committed results in
`1000g_total_results/` were produced on a **2,692-sample** run.

> **ℹ️ Per-tool fixtures are not committed** — they are deterministically
> regenerated from the ground-truth table by `convert_1000g_to_tool_formats.py`
> (**Step 1** below); committing ~7,700 derived files would only bloat the
> repository. The committed result tables in `1000g_total_results/` are the
> reference outputs of the published 2,692-sample run. The
> IPD-IMGT/HLA (pinned via `db-update --imgt-ref 3.64.0`), GWAS, PharmGKB, and
> AFND snapshots are likewise fetched with `db-update`, not bundled, and are
> checksum-verifiable (each `version.json` records a per-file SHA-256).

## Prerequisites

### 1. Install HLAnte in development mode

```bash
pip install -e ".[dev]"
```

### 2. Download the IMGT-HLA database

The benchmark requires the IPD-IMGT/HLA allele table to be present locally.
Run the database update command once before any benchmark run:

```bash
hlante db-update --db imgt
```

This fetches the IPD-IMGT/HLA release (~10 MB) and caches it under
`~/.hlante/imgt_hla/`. To pin a specific release (rather than the moving
`Latest` branch) — required to reproduce the published v3.64.0 numbers:

```bash
hlante db-update --db imgt --imgt-ref 3.64.0
```

## Step 1 — Generate the per-tool fixtures (required first)

The per-tool fixtures are **not committed** to the repository (they are
deterministic conversions of `1000g_HLA_types.tsv`). Generate them once before
running the benchmark:

```bash
python scripts/benchmark/convert_1000g_to_tool_formats.py \
    --input  benchmarks/1000g_HLA_types.tsv \
    --output benchmarks/fixtures_1000g/
```

This writes `benchmarks/fixtures_1000g/{arcashla,t1k,hlahd,optitype}/` (one file
per sample per tool). The script validates every allele cell against
`^\d{2,3}(:\d{2,3})*$` and writes corrupt values to `corrupt_alleles.log`
rather than propagating them. (`benchmarks/fixtures_1000g/` is git-ignored.)

## Step 2 — Run the annotation benchmark

### Full benchmark (all committed fixtures, all 4 tools)

```bash
python scripts/benchmark/run_annotation_benchmark.py \
    --fixtures-dir benchmarks/fixtures_1000g/ \
    --ground-truth benchmarks/1000g_HLA_types.tsv \
    --output-dir   benchmarks/1000g_total_results_v2/ \
    --input-source validated \
    --threads 8
```

Expected runtime: ~15–25 minutes on an 8-core machine.

### Quick smoke-test (30 samples)

```bash
python scripts/benchmark/run_annotation_benchmark.py \
    --fixtures-dir benchmarks/fixtures_1000g/ \
    --ground-truth benchmarks/1000g_HLA_types.tsv \
    --output-dir   benchmarks/smoke_30/ \
    --input-source validated \
    --max-samples  30
```

### Using a pre-selected stratified subset

To create a reproducible N-sample subset that guarantees clinical-allele
carriers are represented:

```bash
python scripts/benchmark/select_stratified_subset.py \
    --input  benchmarks/1000g_HLA_types.tsv \
    --output benchmarks/subset_100.tsv \
    --n 100
```

Then run the benchmark against the subset:

```bash
python scripts/benchmark/run_annotation_benchmark.py \
    --fixtures-dir benchmarks/fixtures_1000g/ \
    --ground-truth benchmarks/subset_100.tsv \
    --output-dir   benchmarks/subset_100_results/ \
    --input-source validated
```

### All CLI flags

| Flag | Default | Description |
|------|---------|-------------|
| `--fixtures-dir` | `benchmarks/fixtures_1000g/` | Root dir with per-tool fixture subdirs |
| `--ground-truth` | `benchmarks/1000g_HLA_types.tsv` | Sanger-validated reference TSV |
| `--output-dir` | required | Directory for all output files |
| `--tools` | all 4 | Comma-separated subset: `arcashla,t1k,hlahd,optitype` |
| `--threads` | `4` | Parallel worker threads |
| `--max-samples` | `0` (all) | Cap per tool (useful for smoke-tests) |
| `--imgt-db-path` | auto | Override IMGT DB path |
| `--offline` | off | Disable live GWAS/PharmGKB queries |
| `--input-source` | `validated` | `validated` suppresses ambiguity penalty for 2-field calls |
| `--log-level` | `WARNING` | `DEBUG`, `INFO`, `WARNING`, or `ERROR` |

> **`--input-source validated`** is the correct setting for the 1000G benchmark
> because the ground-truth genotypes are Sanger-validated at 2-field resolution.
> It disables the ×0.75 confidence penalty that HLAnte normally applies to
> 2-field calls from typing tools.

## Step 3 — Interpret results

### `benchmark_summary.md` / `benchmark_summary.json`

Top-level pass rates across all 6 metric groups:

| Metric | What it measures |
|--------|-----------------|
| `3a parse_rate` | Fraction of fixture files parsed without error |
| `3b norm_rate` | Fraction of parsed alleles successfully normalised to IMGT |
| `3c cpic_recall` | Fraction of CPIC 1A alleles (B\*57:01, B\*58:01, B\*15:02, A\*31:01) correctly flagged |
| `3d gwas_recall` | Fraction of 7 sentinel GWAS alleles with correct trait annotation |
| `3e pop_stratified` | Per-super-population parse + norm rates |
| `3f tier_dist` | Confidence tier distribution (high/medium/low/unresolved) |

### `per_tool_metrics.tsv`

Per-tool breakdown of parse rate, normalisation rate, and allele count.

### `pharm_recall_detail.tsv`

Per-allele CPIC recall: which samples carrying a CPIC allele were correctly
annotated with the drug reaction.

### `gwas_recall_detail.tsv`

Per-allele GWAS recall: which samples were correctly annotated with the
disease association.

### `per_population_metrics.tsv`

Parse and normalisation rates broken down by super-population (AFR, AMR, EAS,
EUR, SAS). Useful for detecting population-specific allele formats.

### `confidence_distribution.tsv`

Counts of `high` / `medium` / `low` / `unresolved` confidence tiers per tool.

### `failed_samples.log`

Sample IDs that raised a parse or normalisation error, with the error message.
Use this to triage any remaining failures.

## Step 4 — Inter-format concordance check (optional)

Verifies that HLAnte produces identical annotations regardless of which typing
tool produced the input:

```bash
python scripts/benchmark/inter_format_concordance.py \
    --fixtures-dir benchmarks/fixtures_1000g/ \
    --output       benchmarks/concordance/concordance_report.md \
    --max-samples  500 \
    --threads      4
```

Produces a Markdown concordance matrix and a detail TSV.
Expected result: ≥ 99.5 % allele identity for arcasHLA / T1K / HLA-HD pairs;
OptiType compared on Class I loci only.

## Known issues and notes

- **OptiType** reports Class I loci (A, B, C) only. DRB1/DQB1 metrics are
  therefore not applicable and excluded from OptiType rows.

- **`--input-source tool`** (the alternative to `validated`) applies a ×0.75
  confidence penalty to 2-field allele calls, as is appropriate for real
  clinical output where exact resolution is not guaranteed.

## Reproducibility status (detail)

- **Ground truth** (`1000g_HLA_types.tsv`): 2,693 Sanger-validated samples.
- **Committed results** (`1000g_total_results/`, `1000g_typingtool_results/`,
  `1000g_supplementary/`): the reference outputs of the published 2,692-sample
  run (`n_samples_total = 2692`; parse rate 99.9% arcasHLA). These tables back
  Tables 2/4/5 and the supplementary tables of the manuscript.
- **Per-tool fixtures**: not committed; regenerate with Step 1. The conversion
  is deterministic, so every tool receives the full set of samples drawn from
  the ground-truth table.
- **Reproducing the exact published numbers**: re-running Step 1 + Step 2
  against the full 2,693-sample ground truth reproduces the pipeline on all
  available samples; the committed result tables are the authoritative
  reference. Database snapshots (IPD-IMGT/HLA pinned via `--imgt-ref 3.64.0`,
  GWAS, PharmGKB, AFND) are fetched with `db-update` and are checksum-verifiable
  (`version.json` records a per-file SHA-256).
